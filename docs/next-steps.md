# Next steps

Ordered by roughly the ratio of payoff to risk. These are larger pieces of work,
each with its own design, and should be separate PRs.

| # | change | why, and what it touches |
| ---: | --- | --- |
| 1 | Make the octree incrementally cheaper, not asymptotically better | The remaining cost is the per-body traversal and the per-step tree rebuild. Candidate work, each measurable by itself: reuse the traversal stack explicitly instead of recursion, tune leaf capacity and `barnesHutMaxDepth` for the measured graph sizes (a shallower tree with a larger bucket is often faster than a deep one), inline the theta test and the distance computation into the traversal, and keep the body-to-cell mapping so an incremental rebuild can skip unchanged cells. [`src/physics/Octree.ts`](../src/physics/Octree.ts). |
| 2 | Remove the remaining main-thread `O(N)` work | After the render worker, exactly two per-frame `O(N)` tasks are left on the main thread: the position copy and forward to the render worker (~98 KB `set()` at 4096) and the depth write-back loop the drag needs. A `MessageChannel` from the physics worker straight to the render worker removes the first (the render worker must exist before the physics worker, and both generations must agree). One simulation worker that owns physics, projection, drawing and hit-testing — so the main thread sends canvas coordinates and reads back a selection index — removes both, at the cost of serialising physics and drawing. Which one is settled when the embedding API is designed. [`src/physics/PhysicsRunner.ts`](../src/physics/PhysicsRunner.ts), [`src/render/RenderRunner.ts`](../src/render/RenderRunner.ts), [`src/physics/PhysicsProtocol.ts`](../src/physics/PhysicsProtocol.ts), [`src/render/RenderProtocol.ts`](../src/render/RenderProtocol.ts). |
| 3 | Physics or rendering beyond canvas 2D | The OffscreenCanvas half of this row landed as the render worker (see [The render worker](model-camera-and-rendering.md#the-render-worker)); what remains for rendering is WebGL (instanced points and lines) rather than further batch tuning. If force computation becomes the wall, the options are a tuned native/WASM kernel, a pool of workers splitting the octree, or GPU forces. Both are separate designs with different failure modes (context loss, shader precision, determinism across devices) and neither is committed. |
| 4 | Package cuniform as an embeddable component | The worker boundary is still demo-shaped: the default worker URLs are hard-coded relative paths ([`src/physics/PhysicsRunner.ts`](../src/physics/PhysicsRunner.ts), [`src/render/RenderRunner.ts`](../src/render/RenderRunner.ts)), so a host's bundler cannot resolve its own asset graph. The component must accept an injected worker factory or URL (the `WorkerFactory` seam already exists for tests) and must import without a `document`, degrading to the in-process path when `Worker`/`OffscreenCanvas` are absent. The published main-thread budget in [Performance](performance.md) is part of the component's contract, not an internal number. |
| 5 | Pack disconnected components instead of letting them overlap | The [component anchor](physics.md) bounds each component's centroid but does not stop two components inside the dead zone from overlapping; inter-component repulsion spreads them without any packing objective. A grid or ring packing pass over the labelling [`graph/Components.ts`](../src/graph/Components.ts) already computes is the follow-up, and it composes with the anchor rather than replacing it. |
| 6 | Let the panel switch between node-priority and edge-priority display | The frame has one emphasis: nodes and edges share the depth ramp, the palette and the painter order, so a dense graph reads the same whether the vertices or the structure are the subject. A panel toggle picks one of two global configurations — no persistence, default `nodes` — and every path must honour the same policy, since the batched and coarse paths already hardcode edges-behind-nodes. Design, phases, measured contrast and acceptance tests: [`docs/workplans/display-emphasis.md`](workplans/display-emphasis.md). Touches [`src/render/Renderer.ts`](../src/render/Renderer.ts), [`src/render/RenderProtocol.ts`](../src/render/RenderProtocol.ts), [`src/render/RenderSurface.ts`](../src/render/RenderSurface.ts), [`src/app/UIController.ts`](../src/app/UIController.ts), [`src/core/K.ts`](../src/core/K.ts) and the panel's static assets. |
